# Technical Decisions

| ID | Date | Decision | Rationale | Status |
|---|---|---|---|---|
| D-001 | 2026-11-03 | Monorepo: `frontend/`, `backend/`, root `docker-compose.yml` | Simple for one team; shared docs. | Proposed |
| D-002 | 2026-11-03 | Postgres, Redis and the video worker run in Docker. API and frontend run natively in dev | No native psql/ffmpeg on the Windows dev machine. Keeps reload fast. | Proposed |
| D-003 | 2026-11-03 | LLM: Anthropic Claude (`claude-opus-5-5`) behind an `LLMProvider` interface. Model per route set in config | Multilingual quality and structured outputs. The provider stays swappable. | Proposed |
| D-004 | 2026-11-03 | AI output is JSON specs only. Visuals come from our own renderers and templated Manim scenes | Never execute untrusted AI-generated code. | Proposed |
| D-005 | 2026-11-03 | Embeddings: local `intfloat/multilingual-e5-base` (768-d) + pgvector HNSW | Free, multilingual, private. | Proposed |
| D-006 | 2026-11-03 | Background jobs with `arq` (Redis) | Async-native and lightweight. RQ needs `fork`, which Windows lacks. | Proposed |
| D-007 | 2026-11-03 | No fine-tuning (PEFT/LoRA) in v1 | Not justified until evaluation data shows that prompting plus RAG falls short. | Proposed |
| D-008 | 2026-11-03 | Gnani: interfaces + mocks + disabled adapters only, until official docs and key are provided | Avoids fabricating an API. | Proposed |
| D-009 | 2026-11-03 | Auth: argon2id, 15-minute JWT access token, rotating hashed refresh token in an httpOnly cookie | Revocable sessions; no long-lived tokens in JS. | Proposed |
| D-010 | 2026-11-03 | Manim scenes use `Text` (no LaTeX) by default | Smaller image, faster renders. | Proposed |
| D-011 | 2026-11-03 | D-001 to D-010 approved with the Phase 0 plan | You approved the plan ("start building"). | Accepted |
| D-012 | 2026-11-03 | Frontend versions from the current Vite template: React 19, Vite 8, TypeScript 7, Tailwind v4 (CSS-first `@theme`, `@tailwindcss/vite`), oxlint | Current stable at scaffold time. Tailwind v4 needs no `tailwind.config.js`. | Accepted |
| D-013 | 2026-11-03 | Readiness checks are injected through a FastAPI dependency (`default_checks`) | Lets tests simulate dependency failures and timeouts without real services. | Accepted |
| D-014 | 2026-11-03 | Integration tests marked `@pytest.mark.integration` and excluded by default | Unit tests run anywhere. Integration tests need `docker compose up`. | Accepted |
| D-015 | 2026-11-03 | Semantic CSS-variable colour tokens (`bg-surface`, `text-muted`, …) with class-based dark mode | One place to theme; avoids `dark:` duplication across components. | Accepted |
| D-016 | 2026-11-03 | Contexts and hooks live in `*-context.ts` files; provider components in `.tsx` | Keeps Vite fast refresh working (oxlint `only-export-components`). | Accepted |
| D-017 | 2026-11-03 | Unbuilt features render real layouts with disabled actions and a `PhaseNotice`; never sample data | Your rule: no fake buttons and no hardcoded data standing in for functionality. | Accepted |
| D-018 | 2026-11-03 | Learner preferences stored in localStorage until Phase 3, then synced to `user_preferences` | Works before auth exists; same context API afterwards. | Accepted |
| D-019 | 2026-11-03 | Built our own Modal/Tabs/Toast (no headless UI library) | Small, accessible, tested; avoids a dependency for three components. | Accepted |
| D-020 | 2026-11-03 | CSRF: custom-header check (`X-CSRF-Protection: 1`) on cookie routes instead of a double-submit token (changes ARCHITECTURE §8) | Only refresh, logout and change-password use the cookie; a custom header forces a CORS preflight, which the allowlist blocks. Simpler, with no token to sync. | Accepted |
| D-021 | 2026-11-03 | Refresh rotation has a 30 s grace window: re-use of a just-rotated token returns `refresh_race` (the client retries) instead of revoking every session | Two tabs refreshing at once must not log the user out everywhere; real reuse after the window still revokes all sessions. | Accepted |
| D-022 | 2026-11-03 | Another user's resources return 404, never 403 | Doesn't confirm that someone else's IDs exist. | Accepted |
| D-023 | 2026-11-03 | Backend tests run against a separate `aitutor_test` DB (migrated by Alembic, truncated per test) and Redis DB 15; skipped with a message if Docker services are down | Real Postgres behaviour (CITEXT, enums, cascades); no mocks of the database. | Accepted |
| D-024 | 2026-11-03 | Theme stays a per-device setting (localStorage); language and level sync to the account | Theme is usually device-specific; the learning preferences follow the learner. | Accepted |
| D-025 | 2026-11-03 | Dev uvicorn runs with `--reload-dir app` | Watching `.venv` made `pip install` trigger a reload that hung. | Accepted |
| D-026 | 2026-11-03 | UI redesign: warm ivory + charcoal "pop" style (ink outlines, hard offset shadows), electric purple/lavender, sun, tangerine, mint; Bricolage Grotesque display + Plus Jakarta Sans body | Your redesign brief: premium, playful, game-inspired, not a generic admin panel. | Accepted |
| D-027 | 2026-11-03 | All illustrations are hand-built inline SVG React components (`components/illustrations`) with a fixed palette | One consistent style, no stock images or licensing, tiny payload, scalable, theme-independent. | Accepted |
| D-028 | 2026-11-03 | Animation via `motion` (Framer Motion) wrapped in `MotionConfig reducedMotion="user"`; reveals render immediately and CSS keyframes are disabled under `prefers-reduced-motion` | Accessibility; content never depends on an animation firing. | Accepted |
| D-029 | 2026-11-03 | New Language Learning section (`/app/languages`, 8 world languages, CEFR A1–C2) added to Phase 9 scope; UI only for now (language/level saved locally, practice disabled, sample flip-cards labelled as samples) | Requested in the redesign brief; backend changes were out of scope for this task. | Accepted |
| D-030 | 2026-11-03 | Navigation regrouped (Learn / Visualise / Track / You) with your 8 brief items; Whiteboard, Quizzes and Lesson History kept | Preserve all existing functionality. | Accepted |
| D-031 | 2026-11-03 | Playwright added as a dev dependency (used for visual checks now, E2E in Phase 14) | Unit tests can't catch layout and visual regressions. | Accepted |
| D-032 | 2026-11-03 | `LLM_PROVIDER=auto`: Anthropic when `ANTHROPIC_API_KEY` is set, otherwise the mock; the UI shows "Mock AI" whenever the mock is active | Keyless local development without hiding that answers are placeholders. | Accepted |
| D-033 | 2026-11-03 | Claude calls use `client.beta.messages.{stream,parse}` with `fallbacks="default"` (beta `server-side-fallback-2026-07-01`); refusals are checked via `stop_reason` and shown as a friendly message | Recommended refusal handling for Opus 5.5; a declined request is retried server-side on a suitable model. | Accepted |
| D-034 | 2026-11-03 | Tutor replies stream as SSE over `POST` (fetch + ReadableStream on the client), not WebSockets | One-way token streaming; works through the Vite proxy and normal auth headers. WebSockets are kept for the voice tutor (Phase 8). | Accepted |
| D-035 | 2026-11-03 | The learner message is stored before streaming; the tutor reply is stored only when complete; partial or declined replies are discarded | No half-written answers in history; a failed turn can be retried. | Accepted |
| D-036 | 2026-11-03 | Plans and summaries use plain Pydantic schemas for structured output; sizes are enforced after parsing (`validate_plan`) | Avoids schema constraints the structured-output subset may not support. | Accepted |
| D-037 | 2026-11-03 | Tutor replies are rendered with a small in-house Markdown renderer that never injects HTML | Safe rendering of model output without a Markdown dependency. | Accepted |
| D-038 | 2026-11-03 | Dev uvicorn also uses `--timeout-graceful-shutdown 3` | Reloads hung waiting for keep-alive connections from the Vite proxy. | Accepted |
| D-039 | 2026-11-03 | Gnani adapters exist but always report unavailable, even with credentials set, until official docs arrive; unit tests assert the module has no HTTP imports or URLs | Enforces the "no invented API" rule in code, not just in docs. | Accepted |
| D-040 | 2026-11-03 | Audio uploads are the raw request body (`Content-Type: audio/...`), not multipart; type is checked against magic bytes and size is capped while streaming | Matches a MediaRecorder Blob directly, needs no extra dependency, rejects mislabelled files early. | Accepted |
| D-041 | 2026-11-03 | The mock TTS produces audible tones per word rather than silence | Lets Phase 6–8 playback be checked by ear while being obviously not speech; always labelled "Mock". | Accepted |
| D-042 | 2026-11-03 | Frontend tests use a 5 s Testing Library wait and a 20 s per-test limit | Lazy route chunks and simulated typing exceeded the 1 s / 5 s defaults on a loaded machine (failures reproduced on the unchanged Phase 4 code). | Accepted |
| D-043 | 2026-11-03 | Dictation fills the message box instead of sending immediately; the message is sent as `input_mode: "voice"` even if corrected | Learners can fix recognition errors first; the mode still records that the question was spoken. | Accepted |
| D-044 | 2026-11-03 | One recording per utterance, capped at 60 s, uploaded after stop (no streaming STT yet) | Fits the request/response STT interface; streaming recognition belongs to the voice tutor WebSocket (Phase 8). | Accepted |
| D-045 | 2026-11-03 | Voice Learning transcripts live only in page state for now | Saving them belongs to a conversation, which the voice tutor (Phase 8) creates. | Accepted |
| D-046 | 2026-11-03 | Read-aloud speed is applied in the browser (`playbackRate`), and audio is synthesized at 1.0× | Speed changes take effect immediately and reuse cached audio; the provider's speed parameter stays available for later. | Accepted |
| D-047 | 2026-11-03 | Replies are read in sentence pieces of ≤400 characters, each synthesized on demand with the next prefetched | First audio starts quickly, long replies stay within `SPEECH_MAX_TTS_CHARS`, and stopping wastes little work. | Accepted |
| D-048 | 2026-11-03 | The voice WebSocket authenticates with a `hello` message carrying the access token (not a query string), and checks the `Origin` header | Browsers can't send auth headers on WebSockets; query-string tokens end up in logs; the origin check stops other sites from opening sessions. | Accepted |
| D-049 | 2026-11-03 | A voice session stays authorised for its lifetime; the token is checked at connect and on every reconnect | Keeps long conversations from dropping every 15 minutes; a revoked user is rechecked on each turn (`is_active`). | Accepted |
| D-050 | 2026-11-03 | Spoken replies are synthesized per sentence while the model streams, in a separate task, and sent as ordered audio frames | Speech starts after the first sentence instead of after the whole reply. | Accepted |
| D-051 | 2026-11-03 | Interrupting (or asking something new) cancels the turn; an unfinished reply is not saved | Same rule as text replies (D-035): no half answers in history. | Accepted |
| D-052 | 2026-11-03 | Voice conversations use a spoken reply style (plain sentences, ≤120 words, no Markdown) | Markdown and long answers sound wrong read aloud. | Accepted |
| D-053 | 2026-11-03 | Auto-send transcripts by default, with a per-device switch to review and correct first | Natural conversation by default; correction stays one click away (needed while recognition is imperfect). | Accepted |
| D-054 | 2026-11-03 | The Phase 6 standalone transcript list on Voice Learning was replaced by the voice conversation (dictation in lessons stays) | The review step covers transcript correction; one place to talk is clearer. | Accepted |
| D-055 | 2026-11-03 | `httpx-ws` (dev only) for async WebSocket tests | Starlette's TestClient runs the app in another event loop, which breaks the shared async database engine. | Accepted |
| D-056 | 2026-11-04 | Course practice is generated per session by the model (validated structured output), not taken from a fixed content bank | Every level, topic and language combination without authoring thousands of items; validation drops broken exercises. | Accepted |
| D-057 | 2026-11-04 | Objective exercises are marked by rule on the server, and answers are withheld from the API until submission | The same answer always gets the same mark, and answers can't be read from the network tab first. | Accepted |
| D-058 | 2026-11-04 | Vocabulary uses SM-2 spaced repetition (again/hard/good/easy), with forgotten cards shown again after 10 minutes | Simple, well-known scheduling that fits a per-card review flow. | Accepted |
| D-059 | 2026-11-04 | Speaking is scored by character similarity between the target phrase and the recognised speech | Works across scripts (including CJK) without a pronunciation model; becomes meaningful once real speech recognition is connected. | Accepted |
| D-060 | 2026-11-04 | Conversation practice reuses voice conversations with a role-play system prompt chosen from the linked practice session | One conversation engine for tutor chat, voice and role-play. | Accepted |
| D-061 | 2026-11-04 | Course-language support in the mock speech providers (the mock is language-agnostic); real support is reported per provider | Lets the course UI be developed and tested end to end without implying real Gnani support. | Accepted |
| D-062 | 2026-11-04 | The language evaluation uses deterministic checks (script share, function words, question present) and needs `--yes` before calling a paid model | Cheap, repeatable regression signal per language; no surprise API spend. | Accepted |
| D-063 | 2026-11-04 | RAG migration renumbered after the planned feature migrations (now 0009) | RAG was deferred from Phase 4; 0004 went to language courses. | Accepted |
