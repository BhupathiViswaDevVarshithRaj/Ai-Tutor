| D-027 | 2026-11-03 | All illustrations are hand-built inline SVG React components (`components/illustrations`) with a fixed palette | One consistent style, no stock images or licensing, tiny payload, scalable, theme-independent. | Accepted |

| D-033 | 2026-11-03 | Claude calls use `client.beta.messages.{stream,parse}` with `fallbacks="default"` (beta `server-side-fallback-2026-07-01`); refusals are checked via `stop_reason` and shown as a friendly message | Recommended refusal handling for Opus 5.5; a declined request is retried server-side on a suitable model. | Accepted |
| D-034 | 2026-11-03 | Tutor replies stream as SSE over `POST` (fetch + ReadableStream on the client), not WebSockets | One-way token streaming; works through the Vite proxy and normal auth headers. WebSockets are kept for the voice tutor (Phase 8). | Accepted |

| D-040 | 2026-11-03 | Audio uploads are the raw request body (`Content-Type: audio/...`), not multipart; type is checked against magic bytes and size is capped while streaming | Matches a MediaRecorder Blob directly, needs no extra dependency, rejects mislabelled files early. | Accepted |
| D-041 | 2026-11-03 | The mock TTS produces audible tones per word rather than silence | Lets Phase 6–8 playback be checked by ear while being obviously not speech; always labelled "Mock". | Accepted |

| D-043 | 2026-11-03 | Dictation fills the message box instead of sending immediately; the message is sent as `input_mode: "voice"` even if corrected | Learners can fix recognition errors first; the mode still records that the question was spoken. | Accepted |
| D-044 | 2026-11-03 | One recording per utterance, capped at 60 s, uploaded after stop (no streaming STT yet) | Fits the request/response STT interface; streaming recognition belongs to the voice tutor WebSocket (Phase 8). | Accepted |
| D-045 | 2026-11-03 | Voice Learning transcripts live only in page state for now | Saving them belongs to a conversation, which the voice tutor (Phase 8) creates. | Accepted |
| D-046 | 2026-11-03 | Read-aloud speed is applied in the browser (`playbackRate`), and audio is synthesized at 1.0× | Speed changes take effect immediately and reuse cached audio; the provider's speed parameter stays available for later. | Accepted |
| D-047 | 2026-11-03 | Replies are read in sentence pieces of ≤400 characters, each synthesized on demand with the next prefetched | First audio starts quickly, long replies stay within `SPEECH_MAX_TTS_CHARS`, and stopping wastes little work. | Accepted |
| D-048 | 2026-11-03 | The voice WebSocket authenticates with a `hello` message carrying the access token (not a query string), and checks the `Origin` header | Browsers can't send auth headers on WebSockets; query-string tokens end up in logs; the origin check stops other sites from opening sessions. | Accepted |
| D-049 | 2026-11-03 | A voice session stays authorised for its lifetime; the token is checked at connect and on every reconnect | Keeps long conversations from dropping every 15 minutes; a revoked user is rechecked on each turn (`is_active`). | Accepted |

| D-051 | 2026-11-03 | Interrupting (or asking something new) cancels the turn; an unfinished reply is not saved | Same rule as text replies (D-035): no half answers in history. | Accepted |
| D-052 | 2026-11-03 | Voice conversations use a spoken reply style (plain sentences, ≤120 words, no Markdown) | Markdown and long answers sound wrong read aloud. | Accepted |

| D-054 | 2026-11-03 | The Phase 6 standalone transcript list on Voice Learning was replaced by the voice conversation (dictation in lessons stays) | The review step covers transcript correction; one place to talk is clearer. | Accepted |
| D-055 | 2026-11-03 | `httpx-ws` (dev only) for async WebSocket tests | Starlette's TestClient runs the app in another event loop, which breaks the shared async database engine. | Accepted |
